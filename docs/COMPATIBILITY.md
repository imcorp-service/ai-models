# 호환성 계약

이 목록을 쓰는 서비스는 복사한 클라이언트로 매시간 목록을 받아 씁니다. 목록이 바뀌어도 서비스가 깨지지 않도록 다음을 약속합니다.

## 이 저장소가 지키는 것

1. `schema_version` 은 **1 을 유지**합니다. 버전 1 안에서는 **선택 필드와 enum 값을 추가**만 합니다. 기존 필드의 이름·형식·의미는 바꾸지 않습니다.
2. 구조를 바꿔야 할 때는 `schema_version` 을 올리지 않고 **새 파일(`ai-models.v2.json`)을 따로 게시**합니다. 서비스는 준비되는 대로 옮기고, `ai-models.json`(v1)은 모든 서비스가 옮길 때까지 계속 갱신합니다.
3. 모델 `id` 는 **제공사 직접 API 의 모델 ID** 입니다. 클라이언트는 ID 를 형식을 해석하지 않는 문자열로 다룹니다. 저장소 CI 의 ID 패턴은 바뀔 수 있습니다(예: 대문자·`:` 허용).
4. Bedrock·Vertex·Azure 등 경유 경로의 ID·리전은 필요할 때 선택 필드(`platforms`)로 추가합니다.

## 클라이언트가 지켜야 하는 것

1. **모르는 필드는 무시**합니다.
2. **모르는 값**: provider·kind 는 선택지에서 뺍니다. status 는 정렬 끝에 둡니다. `requires` 의 모르는 플래그는 "코드 업데이트 필요" 로 선택할 수 없게 합니다. 단가의 모르는 `unit` 은 없는 것으로 봅니다.
3. `schema_version` 이 1 이 아니면 받은 목록을 쓰지 않고 캐시 또는 내장 목록을 씁니다.
4. 단가는 `from ≤ 기준일(KST)` 인 항목 중 가장 최근 것을 씁니다. 없으면 단가를 모르는 것으로 봅니다. 별칭(`alias_of`)은 원본 모델의 단가를 씁니다.
5. 적합성 테스트(`conformance/cases.json`)를 복사해 자기 테스트로 돌리고, 복사한 커밋 SHA 를 기록합니다. 이 저장소가 케이스를 바꾸면 다시 복사합니다.
