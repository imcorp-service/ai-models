# 서비스 적용 가이드

새 서비스에 "AI 모델 선택"을 붙일 때 보는 문서입니다. README의 "서비스에서 쓰는 법"이 원칙이라면, 이 문서는 **실제로 여러 서비스에 적용하면서 드러난 함정과 체크리스트**입니다.

## 1. 작업 순서

1. **호출 코드부터 읽습니다.** 모델을 부르는 함수가 실제로 보내는 파라미터(`temperature`, `max_tokens`/`max_completion_tokens`, `thinking`, `tool_choice`)와 응답을 읽는 방식을 확인합니다.
2. **`SUPPORTS`를 선언합니다.** 1번에서 확인한 요청 형식 그대로 적습니다. 파라미터를 아예 보내지 않으면 그 플래그를 지원하는 것입니다. 호출 코드를 바꾸면 `SUPPORTS`도 함께 고칩니다.
3. **조회 클라이언트를 복사합니다.** [`examples/`](../examples)의 언어별 예제를 서비스에 복사하고, 복사한 뒤에는 서비스 코드로 관리합니다.
4. **검증 기능을 붙입니다.** 실제 호출 함수로 짧은 요청을 1회 보냅니다(§3).
5. **저장 규칙을 넣습니다**(§4).
6. **화면을 바꿉니다.** 하드코딩 선택지를 목록 조회로 바꾸고, 검증 버튼과 예외 사유 입력을 붙입니다(§5).
7. **테스트와 변이 검증을 합니다**(§7).

## 2. 목록 조회

- **서버에서만 조회합니다.** 브라우저는 서비스 API를 통해 필요한 필드만 받습니다.
- **전체 시간 상한을 겁니다.** Python `urllib`의 `timeout`은 소켓 동작 1회 기준이라 느린 응답이 계속 오면 3초를 넘깁니다. 별도 스레드나 마감 시각으로 전체를 자릅니다. 응답 크기 상한도 둡니다.
- **실패도 캐시합니다.** 조회 실패 후 60초 동안은 다시 조회하지 않습니다. 목록 서버 장애 때 화면이 요청마다 3초씩 멈추지 않게 하기 위해서입니다.
- **리다이렉트를 따르지 않고 https만 허용합니다.** 목록 응답의 `Location`으로 내부망 주소를 부르게 되는 경로(SSRF)를 막습니다.
- **형식을 검사합니다.** `schema_version`이 다르거나 필수 필드가 없으면 받은 목록을 버리고 캐시 또는 내장 목록을 씁니다.
- **내장 최소 목록은 표시 전용입니다.** 공용 목록을 한 번도 받지 못한 상태에서는 모델 변경을 저장하지 않습니다. 마지막으로 받은 목록의 캐시는 저장 판단에 써도 됩니다.

## 3. 검증

- **실제 호출 함수를 그대로 씁니다.** 검증용으로 요청을 따로 만들면 "검증은 통과했는데 실제 호출은 400"이 생깁니다. 분석·챗봇이 쓰는 함수에 짧은 프롬프트와 짧은 타임아웃만 넘깁니다. 재시도는 하지 않습니다.
- **응답은 텍스트 블록을 모두 모아 읽습니다.** 최신 모델은 첫 블록이 thinking일 수 있어 `content[0].text`로 읽으면 빈 값이 됩니다. 빈 응답은 실패로 처리합니다.
- **실패를 나눕니다.**
  - 429·5xx·타임아웃: 모델·키가 아니라 제공사 쪽 일시 장애일 수 있습니다. 이때만 **예외 저장**을 허용합니다. 제공사 장애 중에도 키 교체 같은 긴급 변경을 할 수 있게 하기 위해서입니다. 조건은 다음과 같습니다.
    - 목록 확인(목록에 있음·`requires` 충족·은퇴 아님)은 통과해야 합니다. 예외는 호출 검증에만 적용합니다.
    - 관리자가 사유(5자 이상)를 적어야 합니다. 사유와 "검증 미완료"를 변경 이력에 남깁니다.
    - 저장 뒤 첫 실제 호출이 실패하면 바로 알 수 있게 오류 로그를 확인합니다.
  - 인증 실패·모델 없음·400: 저장하지 않습니다. 사유가 있어도 마찬가지입니다.
- **오류 문구에서 키를 가립니다.** SDK 예외 메시지에 키 일부가 들어오는 경우가 있습니다.

## 4. 저장 규칙

- **제공사·모델·키 중 하나라도 바뀌면 검증합니다.** 목록에 없는 모델, 은퇴 모델, `requires`가 맞지 않는 모델은 검증 전에 거부합니다.
- **키는 그 제공사 것만 씁니다.** 제공사를 바꿀 때 다른 제공사의 키로 검증하거나 저장하지 않습니다.
- **거부하면 아무것도 저장하지 않습니다.** 모델·키·제공사를 한 트랜잭션으로 씁니다. 일부만 저장되면 "검증하지 않은 조합"이 남습니다.
- **검증 중 다른 관리자의 변경을 막습니다.** 검증 전에 읽은 값과, 저장 직전에 잠금(`SELECT … FOR UPDATE` 등)으로 다시 읽은 값이 다르면 거부합니다.
- **목록 밖 현재값은 유지합니다.** 다른 설정만 저장할 때 모델 값이 바뀌면 안 됩니다. `<select>`는 현재값이 옵션에 없으면 첫 옵션을 보내므로 주의합니다.
- **멀티테넌트는 요청마다 설정을 읽습니다.** 싱글톤 빈에 모델·키를 캐시하면 다른 테넌트의 키로 호출합니다.
- **변경 이력을 남기고 키는 넣지 않습니다.** 누가, 무엇에서 무엇으로, 검증 결과(성공/예외 사유)를 남깁니다.

## 5. 화면·API

- 목록 API와 검증 API는 **관리자 전용**이고, 검증 POST에는 CSRF를 적용합니다.
- 선택지 순서: 현재값 맨 위 → `active` → `legacy`(교체 권장 표시) → `deprecated`(종료일 표시). `requires`가 맞지 않는 모델은 비활성으로 두고 "코드 업데이트 필요"를 표시합니다.
- 출처(`registry`·`cache`·`fallback`)를 화면에 보여줍니다.
- 목록 값은 `textContent`로 넣습니다. `innerHTML`로 넣지 않습니다.
- 직접 입력 칸은 두지 않습니다. 목록에 없는 모델이 필요하면 이 저장소에 PR을 올립니다.

## 6. 단가(비용 계산)

단가는 목록의 `pricing` 을 씁니다(예제의 `price_for` / `priceFor`).

- 조회 순서: **목록 단가 → 서비스 내장 단가표 → 비싼 기본값**. 내장표는 목록을 못 받을 때를 위한 것이라 없애지 않습니다.
- 기준일은 KST 날짜입니다. 과거 사용량을 다시 계산할 때는 그 사용 시점의 날짜를 넣습니다. 목록의 첫 `from` 이전 기간은 목록이 모르므로 내장표를 씁니다.
- 목록 단가는 **표준 조건**(배치·캐시·장문맥 할증·리전 배수 없음) 가격입니다.
  - 비용 **표시**에는 그대로 씁니다.
  - **예산 차단**(월 한도 초과 시 요청 거부 등)에 쓸 때는 자기 요청이 표준 조건뿐인지 코드·테스트로 확인합니다. 확인할 수 없는 조건이면 목록과 내장표 중 **높은 값**을 씁니다. 판정할 단가가 없으면 요청을 막습니다.
  - 목록 단가가 내장표보다 크게 낮으면(절반 미만) 내장표를 쓰고 경고를 남깁니다(목록 오염 대비).
- 모델 ID 는 정확 일치로 찾습니다. 날짜 붙은 스냅샷 ID 는 목록의 별칭이 원본으로 이어 줍니다. 앞부분(`startswith`) 비교는 쓰지 않습니다 — 짧은 ID 가 먼저 걸려 `gpt-4o-mini` 가 `gpt-4o` 단가로 계산됩니다.
- 내장 단가표의 기본값은 비싸게 잡습니다. 싼 기본값은 비용을 적게 보이게 합니다.
- 분석·챗봇 등 여러 곳이 비용을 계산하면 조회 함수를 한 곳에 둡니다.

## 6.1 기본 모델

저장값이 없을 때만 `pick_default` / `pickDefault` 로 고릅니다(권장값 → 같은 등급의 active 모델 → 내장 기본값, 모두 선택 가능 검사). 결과가 없으면 기본값을 비우고 "모델 선택 필요" 를 표시합니다. 저장값은 바꾸지 않습니다.

## 7. 테스트

네트워크 없이 돌립니다(조회·SDK는 가짜로 대체).

- 조회: 성공 후 캐시, 형식 오류 시 fallback, 느린 응답이 전체 상한에서 잘림, 실패 캐시, 만료된 캐시 사용, 리다이렉트 거부
- 필터: 제공사·`kind`·`retired`·`alias_of`·`requires` 불일치 비활성
- 검증: 실제 호출과 같은 요청 형식, 실패 분류, 빈 응답, 오류 문구의 키 마스킹
- 저장: 목록 밖 거부, 거부 시 무저장, 다른 제공사 키 재사용 금지, 일시 장애 + 사유, 목록 밖 현재값 유지, 동시 변경 거부, 로그·응답에 키 없음
- 권한: 비로그인·비관리자 차단, CSRF
- 적합성: 복사한 `conformance/cases.json` 이 모두 통과(복사한 커밋 SHA 기록)

**변이 검증을 1회 이상 합니다.** 핵심 거부 조건(예: 목록 밖 거부, 잠금 비교)을 일부러 지웠을 때 테스트가 실패하는지 확인합니다. 통과하는 테스트가 곧 잡는 테스트는 아닙니다.

## 8. 적용 범위 밖

- **임베딩 모델**은 선택지로 만들지 않습니다. 차원이 바뀌면 기존 벡터와 맞지 않아 재색인이 필요합니다.
- 코드에 모델이 고정된 기능은 먼저 설정(DB·환경변수)으로 옮긴 뒤 이 가이드를 적용합니다.
